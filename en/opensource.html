GNSS Open-Source Catalog

The go-to open-source tools for getting hands-on with GNSS — a quick sense of what each one does

Commercial receivers are black boxes, but with open source you can run each stage — receiving, analysis, signal generation, position computation — yourself. This page groups the classic tools by purpose. Licenses and versions change, so check each official repository for the latest before you adopt one.

Receivers & signal processing — receive and demodulate with SDR

GNSS-SDR

receiver

A full software GNSS receiver. From raw I/Q samples it does acquisition → tracking → nav-message decoding → PVT, all in software.

  • Multi-constellation, multi-frequency (GPS/Galileo/GLONASS/BeiDou, L1/L5, etc.)
  • Works with RTL-SDR, USRP and other SDRs
  • RINEX/KML output to bridge into other analysis tools
C++Apache-2.0GitHub →

PocketSDR

receiver

A lightweight software GNSS receiver (+ a small front-end) by RTKLIB's author. It visualizes acquisition and tracking from raw I/Q — popular for research and teaching.

  • See and learn the 2-D acquisition search and correlation
  • Supports many GNSS signals, including new ones
  • An open small RF front-end design is published too
Python/CopenGitHub →

GNU Radio

SDR framework

A general-purpose SDR signal-processing framework. Wire blocks together to build a receiver or transmitter — the foundation of SDR work.

  • Draw flow graphs in the GUI (GRC) to process signals
  • Not just GNSS — FM and radio in general
  • GNSS-SDR and friends run on/around it
C++/PythonGPLv3GitHub →

SoapySDR

SDR framework

An abstraction layer that exposes SDR hardware through a common API. Drive RTL-SDR / HackRF / LimeSDR / USRP the same way from your app.

  • A driver layer that hides per-board differences
  • Used internally by many receive/generate tools
  • Handles the boards from SDR Basics uniformly
C/C++BoostGitHub →

Positioning, corrections & post-processing — compute the fix / raise accuracy

RTKLIB

positioning

The classic for high-precision GNSS. From observations it does standalone, DGPS, RTK and PPP, both real-time and post-processing — a Swiss-army toolset.

  • cm-level with RTK/PPP (an implementation of corrections)
  • RINEX conversion, base-station data handling, many formats
  • GUI (RTKNAVI etc.) and CLI (rtkrcv / rnx2rtkp)
CBSD-2GitHub →

gnsstk (ex-GPSTk)

library

A parts-box library for GNSS processing — orbit computation, time systems, coordinate transforms, RINEX handling — the base for building your own positioning app.

  • Functions to compute satellite position from ephemeris
  • Coordinate transforms like ECEF ↔ lat/lon
  • C++ core with Python bindings
C++/PythonLGPLGitHub →

laika

library

A Python GNSS library from comma.ai. Pseudorange correction and positioning in readable code — good for research and experiments.

  • Implements ionosphere, troposphere and satellite-clock corrections
  • From raw observations to a position, in Python
  • A practical library from the self-driving world
PythonMITGitHub →

georinex

data

A Python tool to read RINEX (observation & navigation), GNSS's standard data format — the classic entry point for analysis.

  • RINEX 2/3 obs/nav files into xarray/pandas
  • Handy for pre-processing large observation logs
  • A base for your own analysis and plotting
PythonMITGitHub →

RINGO

data

A Go-based RINEX toolkit published by GSI (Japan's Geospatial Information Authority). Convert, edit, merge and quality-check observation/navigation data from the command line.

  • RINEX conversion, editing, merging, quality check (QC)
  • Handy for Japan's GEONET reference-station data
  • A single-binary, practical tool from a public agency
GoGSIFind on GitHub →

Signal generation & testing — build a GNSS signal

gps-sdr-sim

generator

The classic that generates an I/Q file of GPS L1 C/A for any position and time, replayed through an SDR to test receivers.

  • Give it nav data (RINEX) + a location to synthesize I/Q
  • Replay via LimeSDR etc. (see GNSS TX with SDR)
  • Radiating is illegal: cable + attenuators, your device only
CMITGitHub →

Derived simulators

generator

Various generators derived from gps-sdr-sim, some adding Galileo, QZSS, multi-GNSS or dynamic scenarios.

  • Multi-GNSS variants (e.g. galileo-sdr-sim)
  • Some accept a moving trajectory (NMEA/motion) input
  • All assume a closed, wired setup
C/C++variousGitHub topics →
Where should I start? — recommended entry points

Experience receiving first: an RTL-SDR (TCXO version) + a patch antenna + GNSS-SDR or PocketSDR. Acquiring and tracking real L1 and watching the blocks from the Receive Chain actually run is a genuine thrill.

Try high-precision positioning: public reference-station RINEX data + RTKLIB. Run post-processing (rnx2rtkp) with RTK/PPP first and watch the error shrink to cm on your own data, exactly as on the Corrections page.

Build the signal itself: generate I/Q with gps-sdr-sim → replay via SDR. But as on GNSS TX with SDR, always use a cable + attenuators — radiating over the air is illegal.

Analyze in code: read RINEX with georinex, then compute satellite positions, corrections and fixes with gnsstk or laika. You can follow the whole flow in Python.

Notes on licenses and use

The licenses and support noted here are approximate as of writing. When you actually use a tool, check each repository's LICENSE and README (commercial-use and redistribution terms vary by license).

Signal generation tools need special care. Radiating in the GNSS bands over the air is illegal in virtually every country, and deceiving someone else's receiver is a crime. Always test over a direct coax cable + generous attenuation, or inside a shield box, against your own equipment only (see the Jamming & Spoofing page too).
